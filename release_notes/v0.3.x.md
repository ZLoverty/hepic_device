# v0.3.x

## v0.3.5

- 将质检页面的列改为可滚动，避免内容过长，超出页面的内容被裁剪。

## v0.3.4

- HEPiC 依赖改为从腾讯云 COS 镜像的源码包安装：`pyproject.toml` 里的 `HEPiC @ git+https://github.com/ZLoverty/HEPiC.git@master` 改为普通版本约束 `HEPiC>=1.6.1`（pip 处理 VCS URL 时会无视 `--index-url` 直连 github.com，这样就绕不开了）；新增 `scripts/fetch_hepic.sh`（优先 COS 镜像、失败回退 GitHub tag 包，逻辑与 `fetch_src.sh` 一致），`install.sh` 第 1 步在 `pip install -e .` 之前先用该脚本下载并安装 HEPiC
- 新增 `scripts/install_from_cos.sh`：全新设备的一键引导脚本，从 COS 的 `latest.json` 解析最新 tag，直接下载 `hepic-device-src-<tag>.tar.gz`（不走 GitHub 回退，专门给连不上 GitHub 的场景用）解压覆盖到 `$HOME/hepic_device`（可用 `TARGET_DIR` 环境变量覆盖），再自动 `cd` 进去执行 `install.sh`，作为设备上 `git clone` 的替代方案

## v0.3.3

- 前端整体换成亮色主题：背景从深色（`#141824`）改为白色，全站字号统一提到 ≥20px，涉及 `App.svelte`、`LineChart.svelte`、`NavBar.svelte`、`QcHistoryList.svelte`、`Dashboard.svelte`、`QualityCheck.svelte`、`Settings.svelte` 等页面，固件告警横幅等配色同步调整以便在亮色背景下依旧醒目
- 质检历史面板支持横向滚动：日期标头改为左右都 `sticky`，行内容不再用省略号截断而是随面板整体横向滚动，并加了自定义细滚动条样式，避免长文本被裁切看不全
- COS 地址从占位符改成正式配置好的桶域名（`scripts/fetch_src.sh` / `scripts/fetch_static.sh`）；`fetch_src.sh` 改为先解压到临时目录、再 `cp -a` 覆盖到目标目录，不再依赖压缩包里固定的文件夹名；`scripts/update.sh` 由原来单纯 `git pull` 改为版本比较逻辑——解析本地 `backend.__version__` 与 COS（失败则回退 GitHub API）上的最新 tag 比较，只有落后时才拉取源码包重装，避免每次触发更新都做一次无意义的重装

## v0.3.2

- 质检页面「开始质检」按钮改为依赖 Klipper 就绪状态（`klippy_state === 'ready'`）才可点击，未就绪时按钮置灰并显示「Klipper 未就绪」提示，避免固件还没准备好时误触发质检
- 设置页面布局调整：「材料数据库」「系统更新」两个区块合并进「关于」分组展示，版本号等信息与更新操作放在一起，减少页面滚动
- 温度设置的输入范围从 20–320℃ 放宽到 0–360℃，此前设置 0 无法生效（被 `v >= 20` 挡住）

## v0.3.1

- 质检结束或中止后统一改为「急停 + 固件重启」（`abort_and_recover`），尽快把温度降下来：后端新增 `POST /api/klipper/abort_and_recover`，对应 `DeviceKlipperWorker.abort_and_recover()`（先 `emergency_stop` 再 `restart_firmware`），逻辑与 PC 端 `KlipperWorker.abort_and_recover()` 保持一致；质检正常完成、手动中止两条路径都改走该接口，不再只是单纯急停（一次性 gcode 脚本没有取消/暂停机制，无论是中途中止还是跑完自然结束，都得靠急停清空队列 + 固件重启才能让 Klipper 回到「就绪」）
- 主页新增「传感器清零」按钮，可直接点击触发清零，不必等待 M118 回传 `ZERO_SENSORS` 文本才被动触发；顺手去掉温度设置按钮上多余的「点击设置 ✎」提示文案，视觉更简洁
- 修复传感器 WebSocket 连接：客户端在网络异常下线、Starlette 还没来得及抛出 `WebSocketDisconnect` 之前底层 write 失败，后端偶发抛出未捕获异常刷屏日志的问题
- 树莓派 OTA 更新脚本 `scripts/update.sh` 固定拉取 `main` 分支（若当前不在 `main` 分支会先自动切换），避免设备停留在旧分支上收不到更新

## v0.3.0

- 主页 Dashboard 重新布局：挤出/回抽与温度设置合并为一组，急停按钮挪到更远的角落避免误触，新增「质检历史」侧栏面板（放大按钮字号，收紧面板宽度到刚好显示全部内容，历史条目做了单行显示避免换行）
- 质检历史改为持久化存储：
  - 后端新增 `GET /api/qc/history`（分页读取，默认最近 200 条）与 `POST /api/qc/history`（每次质检结束后由前端写入一条记录），落盘到 `HEPiC.database.QcHistoryStore`（SQLite），不再是重启即丢的内存列表
  - 前端启动时从 `/api/qc/history` 拉取历史记录填充侧栏，历史面板按日期分组显示（同一天的记录只显示一次日期标头）
- 修复质检历史面板与质检页面「冻结力值」显示不一致的问题：抽出共享的 `forceWindow.js`（滚动窗口最近 200 个样本、至少 10 个才出结果，逻辑对齐 HEPiC 的 `evaluate_force_window`），两处统一调用
- 正确处理 `ZERO_SENSORS` 指令：后端新增 `POST /api/klipper/zero_sensors`，对所有可清零传感器执行清零；前端监听到 M118 回传的 `ZERO_SENSORS` 文本时会调用该接口触发动作，而不是被后续的 `STOP_QUALITY_CHECK` 分支吞掉
- CI/CD：GitHub Actions 发布流程新增源码包（`git archive` 打包的纯源码，不含 `.git` 与 gitignore 掉的 `backend/static`）与 checksum 文件，并将静态前端包、源码包、checksum 三个产物同步镜像到腾讯云 COS，方便无法直连 GitHub 的树莓派设备下载；新增 `latest.json` 指针供设备解析「最新稳定版」，只有非预发布 tag 才会更新该指针
  - 新增 `scripts/fetch_src.sh`：优先从 COS 镜像、失败则回退到 GitHub Release 下载源码包，作为 `git clone` 的替代方案
  - `scripts/fetch_static.sh` 同步适配新的 COS 镜像与产物命名规则
  - 期间修复了一版产物命名不一致的问题（`hepic-device-<tag>-static/src.tar.gz` 统一改为 `hepic-device-static/src-<tag>.tar.gz`）
